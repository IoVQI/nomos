# 项目改进与维护宗旨 — 工作备忘录的准入与处理准则

> 本准则约束**工作备忘录事项的生成与处理**（台账 + 会话/审计报告中的改进建议）。
> 它是**判断层**文件：不配脚本、不设闸门、不计数——配套机制一律复用现有设施
> （生成视图、检查脚本、会话报告工作流）。它只回答两个问题：
> **什么值得进表**（§1）与**怎么处理与收尾**（§2）。
>
> 科研备忘录（由用户直接裁决的条目）不受 §1 闸门约束。

## §0 总则：科研是目的，工程是手段

1. **收益归宿**：项目的第一身份是科研辅助工具。任何工程改进必须能回答
   「**保护了什么科研产出、避免了什么实际损害**」；答不出的，不进工作备忘录。
2. **不完美是稳态**：非阻塞漂移、历史残留、一次性不一致，默认属于「**已知可接受残留**」，允许长期存在。
   登记 ≠ 必修；不修是裁决，不是遗漏。
   **落地处**（裁决须留下痕迹，否则下一会话无法继承）：当次审计/评估/会话报告的「残余风险」节。
   §1 判「不挂表」的事项记在这里，不进台账；仅当它日后造成实际损害时才按 §1 重新立项。
3. **本宗旨不产生新机制**：它把散落的既有教训收编为一张准入门槛；它自身不消耗算力，
   省算力的方式是**让不该进表的条目不进表**——条目是债务，每条都携带未来的处理成本。

## §1 准入闸门（生成侧）

写条目（会话报告 / 台账直写）前逐条过以下四问。**组合规则 = 析取默认拒绝**：
**任一问落到该行判定线的拒绝侧即构成否决**——不是「四问皆否才拒」。
条目的合法来源只有三类：真实的失败/事故/缺口、用户显式要求、可验收的科研改进；
其中**「用户显式要求」与「附『已复发』实证」是仅有的两个例外**，可覆盖拒绝侧判定，
但须在条目 `source` 写明依据。

> 🔴 **本闸门对 P1 / P2 / P3 一律适用，不按优先级豁免**：默认拒绝清单瞄准的
> 「为保险起见加个校验」「把文档再写全一点」正是 P3 类条目，而 P3 往往是活跃台账中量最大的一类。
> 豁免 P3 等于放空闸门的主要靶区。
>
> 🔴 **接线处只引本条 §1，不得自行复述范围**——**范围以 §1 为唯一真源**。
> 复述即产生第二真源：多处接线各写一份范围，迟早失同步，甚至把另一接线点当成真源。

| # | 问题 | 判定线 |
|:--:|------|------|
| 1 | **证据问**：它防的是**已实际发生**的失败（有复发记录 / 事故锚点），还是假想失败？ | 假想 → 默认拒绝 |
| 2 | **归宿问**：修复后受益者是科研流程（入库 / 复现 / 推导 / 数据 / 写作），还是仅治理账面？ | 仅治理账面 → 默认拒绝，除非它阻塞科研流程 |
| 3 | **成本问**：修复成本 vs 不修的预期代价（一次性瑕疵 vs 复发性损耗）？ | 修不如放 → 记为「已知可接受残留」，不挂表 |
| 4 | **手段问**：能否用**结构约束**（模板占位符 / 单写者 / 生成视图 / 既有脚本闸门）解决，而非再加一条**文本提醒**？ | 文本提醒边际递减 |

**默认拒绝清单**（除非附「已复发」实证，否则不立项）：

- 「为保险起见加个校验/闸门」——缺乏实际事故锚点的防御性设施
- 「定期间隔提醒 / 周期性审计」——**间隔本身不防 drift**；按需驱动，不按日历驱动
- 「新增计数 / 评分 / 阈值设施」——见 CLAUDE.md 计数描述退役原则（判定三问）
- 「全量清理历史残留」——没有明确损害面时，成本高于收益
- 「把文档再写全一点以防遗忘」——文本提醒的手段问，边际递减

**准入质量三条**：

1. **可验收**：「做完的判据」一句话写得出来；写不出 → 只记录为观察，不立项
2. **带锚点**：来源（报告编号 / commit / 事故现场）+ 触发条件，不写情绪化描述
3. **先查重**：写入前 grep 台账 `title` 与正文，按语义比对同族条目，避免重复挂表。
   🔴 编号解析工具**不能用于查重**——它只匹配 id / 历史编号，不做关键词检索。

## §2 处理与收尾（处理侧）

1. **优先级 = 不做的代价**（不是想做的程度）：
   - P1 = 正在造成实际损害或阻塞科研推进
   - P2 = 已复发且不修的累积成本可观
   - P3 = 其余（含纯改进愿景）——出口是陈旧度报告（长期无活动 → 列出待裁决，**不自动关闭**）
2. **按需驱动，禁止周期驱动**：不设时间间隔型提醒与定时审计；触发必须来自真实事件
   （校验 FAIL / 用户显式 / 链编排）。
3. **根因优先 + 同族扫描**：单点修复前先查同类问题是否在别处存在。执行时遵循
   CLAUDE.md 的调试纪律（4 阶段门控、3 次失败规则）——**引用，不复制**。
4. **终态纪律**：每条事项必须有终点。长期无进展且无阻塞 → `dormant`；不再适用 → `dead` / `superseded`；
   完成 → `done` + 关闭时间 / 原因。不做无限期 `active`。
5. **退役对称性**：新增任何设施时，须一并写明它的**退役判据**（什么条件下它该消失）；
   执行退役时按**四层**残留核查：

   | 层 | 核查对象 | 检索手段 |
   |:--:|---|---|
   | ① 闸门层 | 提交钩子、CI、校验脚本 | `grep -rn --exclude-dir=__pycache__ "<设施名>" .pre-commit-config.yaml .github/workflows/ ai_system/validation/`。`--exclude-dir` 防已删脚本的陈旧 `.pyc` 报假命中 |
   | ② 工作流正文指令层 | 工作流中的祈使句 | `grep -rn "<设施名>" ai_system/workflows/ CLAUDE.md`。判据是「**是否仍在指令写/读**」，不是「是否被提及」（历史注记不算） |
   | ③ 虚假宣称层 | 「文档仍声称它在校验」 | `grep -rnE "<设施名>|<退役字段名>" ai_system/workflows/ \| grep -E "校验\|检查\|闸门\|强制"`，再逐条回**校验器代码**确认闸门是否真在校验它（文档说什么不算） |
   | ④ 记忆层 | 仓库外的会话记忆 | `grep -rn "<设施名>" <memory 目录>`，逐条判定「历史案例（可留）/ 现行指引（须改或标退役）」 |

   🔴 **第三层最误导**——它伪装成安全网，让人以为对象受保护；**第四层最不可见**——
   记忆不在仓库内，无 grep 面、无 CI，是唯一不会被任何闸门发现的残层。
   清单**只生成候选，定性回落内容层**；不建脚本（§4）。
6. **单写者与生成视图**：共享台账 / 索引同一时刻只有一个写者；能从真源生成的一律不手写。
   跨会话协作见 [`coordination/`](../../coordination/README.md) 规程。
7. **大动作走方案**：结构性变更（新目录层级、≥5 文件重命名、设施退役）先走
   `Skill: proposal-gen`（生成即审计）；不可逆操作按 CLAUDE.md 的不可逆操作确认原则。

## §3 自律设施预算（反膨胀条款）

**自律设施**指：闸门、校验脚本、计数、评分、周期提醒、状态机械——一切「为了约束自己」而存在的工程。

**默认拒绝 · 实证解锁**：

1. 新增一个自律设施，必须同时满足：
   - a. 附「**它要防止的错误已实际复发**」的实证（现场锚点，不是预判）；
   - b. 说明它**简化或替代**了什么（一进一出优先；净增复杂度须给出理由）。
2. **项目对设施总复杂度负责，不对单个设施的局部合理性负责**——每个设施单独看都合理，
   加起来就是臃肿与算力浪费。裁决对象是总量，不是单项。
3. 已有设施的退役与新建**同等重要**：建设时写明退役判据（§2-5），审计时优先找可退役项。
4. 设施的价值证明方式是「**它拦下过 / 防止过什么实际事故**」，不是「它覆盖得多全面」。

### §3.1 闸门作用域原则

> **一句话**：**闸门的阻断面不得超出提交者的控制面**；超出部分只能**报告**，不能**阻断**。
> ①② 讲「闸门看**谁**」，③ 讲「闸门看的**东西**是不是它以为的那个东西」——同属**评估面**的正确性。

| 条 | 原则 | 判据 |
|:--:|---|---|
| ① | **阻断面 ⊆ 控制面** | 若一个闸门会在「提交者**无论如何暂存**都过不去」的状态下 FAIL，它的评估面就**越界**了——要么把结果降级为**报告**，要么把评估面收窄到**本次改动可归因**的范围 |
| ② | **扩大作用域前须做全仓影响面评估** | 新增判据、或把闸门从「逐文件」扩到「全仓」之前，**先跑一遍全量并数清存量欠账**，并给出「存量怎么办」的显式处置。不做评估即上线 ⇒ 把**与你无关的既有失败**变成所有人的阻断源 |
| ③ | **匹配口径须与语料实盘对拍** | 判定的正则/模式与实际语料形态不匹配时，**同一根因会同时产出两类反向故障**：**假 FAIL**（误拦本无问题的提交）与**假 PASS**（漏拦真实缺陷）。约束：任何**计数 / 枚举 / 存在性**类判据，必须在同一输出里同时打印「**匹配数**」与「**实际条目数**」（或等价的实盘口径），差额为 0 或已解释；**只打印匹配数、不与实盘对拍的判据，视为未验证** |

**三类典型失效**（与具体项目无关，用于设计/审计闸门时对照）：

| 形态 | 现场特征 | 可复算判据 |
|---|---|---|
| **评估面错配**（①） | 闸门校验「生成物 vs 真源」，而真源在另一会话在途；提交钩子的临时索引把他人已暂存件判为未暂存 ⇒ 任何暂存组合都 FAIL | 闸门退出码 1，且在干净重生成后转绿 |
| **作用域越界**（②） | 新判据在 CI 无条件全量运行，撞上大量存量文件 ⇒ 主干必红、任何 push 都红 | 全量 FAIL 计数 > 本次改动引入的失败数 |
| **判据口径失配**（③） | 正则把全文引用当成目标引用；`^` 未加多行标志导致「一行都删不掉」而脚本不报错 | **假 PASS 侧零信号**——只有同时打印「匹配数 vs 实盘行数」才暴露差额；**假 FAIL 侧**的报错指向真实存在的文件，人易先怀疑路径而非判据 |

> 🔴 **本条不新增设施**（§0-3）：它是**判断层**条文，供闸门的设计与审计引用。
> ③ 的载体是**既有脚本的输出约定**（多打印一个对拍数），不是新闸门。

> **同族教训**：子串自反（验证命令被自己的引述句命中）、时序误标、前缀截断、
> 废止记录自反、判据表自冲突——这些失败信号与真失败**同形**；
> 正则计数须与总行数对拍；排除模式可能五向出错。

## §4 本宗旨自身

- **一页纸**。实质扩写前先问：这是新规则，还是既有教训的重述？
- **条款须附实践出处**（案例 / 报告 / commit）；无案例的条款不写入——防空话。
- **不设脚本强制**：不新增校验脚本、不加 pre-commit 钩子、不进 CI。本宗旨指导判断，
  而判断点（进表、收尾）没有脚本可替代；若某天发现「需要脚本才能执行本宗旨」，
  这本身就是 §3 要拦截的信号。
- **消费点**（三类**时机**，不需要「定期查阅」）：
  1. **建台账条目时**——过 §1 四问；
  2. **立项时**——过 §1 / §3；
  3. **收尾核销条目时**——按 §2。
  另有一类**非「时机」消费**：新建闸门时按 §2-5 写退役判据——它不执行本宗旨，
  只采用本宗旨的约定，与「不设脚本强制」不冲突。
- **修订**：随实证累积修订；实质重写**只 bump 版本字段，不重编号**——序号一经创建即固定，
  外部引用面广，重编号的爆炸半径远大于收益。
