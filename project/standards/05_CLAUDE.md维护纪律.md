# CLAUDE.md 维护纪律 — 项目指令文件的准入、退场与对账

> 本准则约束 `CLAUDE.md` 这个**载体本身**的三件事：什么能进（§1）、退役了怎么退（§2）、怎么对账（§3）。
> 它是**判断层**文件：条款自身不配闸门、不进 CI；§3 的按需对账脚本是**报告工具**，不是闸门。
> 与 [`06 改进与维护宗旨`](06_改进与维护宗旨.md) 的分工——06 管「什么值得立项、设施怎么退役」
> （本准则 §2 依其 §2-5），本准则只管**承载这些决定的那个文件**。
>
> 🔴 **消费点真值 = 全库 `grep -rn "standards/05"`**（**不在此处枚举**：枚举必然漂移）。

## §0 为什么 CLAUDE.md 需要单独一条纪律

三个别处没有的性质叠加，使它**误述的代价按会话数放大**：

1. **它是每会话启动必然加载的唯一文档**。一行过期的话不会被任何闸门报错，
   而是被此后**每一个**会话默默继承——错误在这里不产生失败信号，只产生一致的行为偏差。
2. **它通常处于零自动维护**。提交钩子、CI 与校验脚本往往只覆盖目录级文件，
   根目录的 `CLAUDE.md` 不在任何闸门的输入里。唯一可能触及它的是退役残留扫描——
   那是**扫它，不是校验它**。
3. **它的维护容易退化为现场手写**。同一需求反复以一次性脚本出现、用完即弃，
   没有沉淀成常驻设施——这正是「每次都手动维护」的形态。

**增长是默认态**：没有退场纪律时，指令文件只增不减。
⇒ **退场需要纪律，因为不写纪律时它只增不减。**

> 复算判据：`python ai_system/validation/check_claude_md.py`（A/B 判定 + C/D/E 实盘）。

## §1 准入：什么能进 CLAUDE.md

**一句话判据：CLAUDE.md 只承载「每会话都必须生效、且没有他处真源」的内容。**

| # | 合法三类 | 判据 | 例 |
|:--:|---|---|---|
| ① | **行为约束** | 不带它，本会话就会做错 | 🔴 禁止使用 `git add -A` |
| ② | **导航指针** | 一句话 + 真值取法 | `workflows/` …（真值：`ls ai_system/workflows/*.md`） |
| ③ | **判定原则** | 跨域准绳，本项目内无他处真源 | 计数描述退役原则·判定三问 |

| # | 拒绝三类 | 判据 | 为什么 |
|:--:|---|---|---|
| ④ | **有他处真源的「事实」** | 同一事实在别处有机器可读落点（清单 / 计数 / 路径 / 字段表 / 状态） | 第二真源 ⇒ 必漂移。**处置是删镜像，不是加校验**——镜像行与真源不一致时，校验只会让两处都更难维护 |
| ⑤ | **按需才查的知识** | 只有部分会话用得上 | 占用每会话的常驻上下文；它自有必然加载点（工作流 / 准则 / 域 index） |
| ⑥ | **变更叙事** | 「当初为什么这么改」 | 属方案 / 报告 / 会话记录；CLAUDE.md 只留一行指针 |

> 🔴 **易误读处**：本准则**不禁止复述规则，禁止的是复述事实**。规约是判断层的，无真源可漂；
> 清单、计数、路径、字段表是**事实**，必有一处权威。
>
> 🔴 **与计数描述退役原则的关系**：④ 是那条原则的**上位表述**（把「计数」泛化为「一切镜像事实」）。
> 判定**仍以 CLAUDE.md 中计数描述退役原则的判定三问为唯一真源**，本准则不复述其内容。

**写入动作三条纪律**：

1. **先查重**——写入前 grep CLAUDE.md 同类关键词，避免同族规则两处维护。
2. **先问挂载点**——这条规则**谁在什么时候会读到**？答不出 ⇒ 它大概率该待在工作流里，不在这里。
3. **不写死数字**——需要规模时写真值取法，不写快照。

## §2 退场：设施退役后，CLAUDE.md 里那一段怎么办

### §2.1 墓碑的唯一存在理由

CLAUDE.md 里的退役段落（下称**墓碑**）只有一个用途：**防止读者把已死设施当活的**。
除此之外它不承载信息——退役依据、实证数据、方案链接都属于方案文件。

**判据**：该设施名在**活跃内容层**还会被读到吗？

- 会（工作流正文 / 台账 / 记忆仍引用）⇒ 保留墓碑；
- 不会 ⇒ 墓碑可删；**删前按 06 §2-5 确认四层残留已清**。

### §2.2 处置阶梯（两档，原地降级）

| 档 | 从 | 到 | 触发判据 |
|:--:|---|---|---|
| **一** | 活规则（机制表 / 参数 / 规则清单） | **墓碑一行**：名称 + 退役日期 + 一行理由 + 方案指针 | 该规则已不生效 |
| **二** | 多个同批墓碑各占一个小节 | 合并进**一个**「已退役设施」清单，每设施一行 | 同批退役 ≥2 项 |

> **先例不是新发明**：把一次性简化动作（多个小节压成一行）成文化，就是本准则的来源。

> **现状检查**：CLAUDE.md 中若仍有多个墓碑各占一个小节，说明档二尚未应用。
> 应用它是一次独立的维护动作，须先过 §2.3 的顺序纪律。本准则不自动追溯存量——
> 纪律不溯及既往地要求立即重写，但存量在下次触碰该区域时按本节收敛。
>
> 🔴 **统计口径**：只数「标题级」墓碑会漏掉写在正文/表格内的退役声明。
> 合并/计数时须把两类都算上。

### §2.3 顺序纪律：**墓碑写在事实之后**

🔴 **先按 06 §2-5 完成四层残留核查，再压缩 CLAUDE.md 的段落。**

**反例**：把「某目录停止新增」先写进 CLAUDE.md，之后才发现执行层仍有写入指令与残留脚本——
**声明先于事实，随即被证伪**，不得不二次修订为「补完退役」。
⇒ 墓碑里那句「已退役」**本身是要被核实的断言**，不是可以顺手写下的措辞。

### §2.4 两条禁止

- **禁止把 CLAUDE.md 当退役记录簿**——叙事进方案文件，此处只留一行指针（§1 ⑥）。
- **禁止设「定期重读 / 定期清理 CLAUDE.md」的提醒**——06 §2-2 已裁定「按需驱动，禁止周期驱动」，
  间隔本身不防 drift。

## §3 对账：可核验声明与实盘

**设施**：`python ai_system/validation/check_claude_md.py`（按需运行）

| 节 | 检查 | 判定 |
|:--:|------|:---:|
| A | 含斜杠的根相对路径存在性（**强引用**＝反引号跨度与链接目标） | FAIL 影响退出码 |
| A-弱 | 链接**文本**里的路径缺失（文本多是引用，也可能是纯标签，机械判据分不开） | WARN，只报告 |
| B | 点名的命令行参数在**同行宿主脚本**中是否声明 | FAIL 影响退出码 |
| C | 计数型声明候选（清单，供人过判定三问） | INFO |
| D | 墓碑体量与 🔴 语义分布 | INFO |
| E | 体量（每会话常驻成本） | INFO |
| A′ | 无斜杠的具名引用 | INFO，**不判定** |

**何时跑**：① 改 CLAUDE.md 前 / 后；② 执行任一设施退役后（06 §2-5）；③ 用户或链显式触发。

**三条边界（必须写明，否则设施会被误用）**：

1. **它是报告，不是闸门**——**不进 pre-commit、不进 CI**。依据 06 §3.1 ①「阻断面 ⊆ 控制面」：
   CLAUDE.md 的历史欠账不该拦住一次与它无关的提交。
2. **它不判语义**——「某条规则是否仍有效」「某段复述是否已漂移」无机械判据，回落人读。
   脚本列清单，人裁决。
3. **A′ 的「未解析」不等于失效**——禁用旧名、已删对象、历史引文、字段名都在这一桶里。

> **快照会过期，判据不会**：不要在本文维护「当前有 N 个路径 / N 个墓碑」的读数；
> 需要规模信息时现场跑脚本。

> 🔴 **🔴 的语义**：CLAUDE.md 用 🔴 标「此处是硬约束」。当它被大量用于变更史记录时会**稀释该信号**
> （读者对红点的条件反射失效）。**新增变更史注记时优先不用 🔴。**

## §4 与既有设施的关系（一进一出）

| 方向 | 对象 | 说明 |
|---|---|---|
| **接手** | 一次性对账脚本 | 把「每次维护现场重写一个探针」升格为常驻、可复算的报告工具 |
| **不替代** | `standards/06 §2-5` 四层残留核查 | 06 管「设施退役」的完整性，本准则管「CLAUDE.md 这个文件」的状态。**层数与检索手段以 06 §2-5 为唯一真源，不在此复述** |
| **同型** | `ai_system/validation/check_memory.py` | 同为「按需运行、不进 pre-commit / CI」的读侧维护设施 |
| **不新增** | 闸门 / 计数设施 / 周期提醒 | 见 06 §3 默认拒绝清单 |

## §5 退役判据（依 06 §2-5）

出现下列任一情形，本准则 + 对账设施应退役：

1. **对账脚本连续 3 次运行零发现**（A/B 全绿且 C/D/E 无新信息）⇒ 声明已收敛，
   把 §3 降级为**复算命令清单**并删除脚本（这就是本设施「全绿」的可判定含义）；
2. `CLAUDE.md` 不再每会话加载（被分段加载 / `.claude/rules/` 等取代）⇒ 载体变了，失去对象；
3. 上游出现等价的官方机制（工具自带 `CLAUDE.md` 校验）⇒ 被覆盖。
