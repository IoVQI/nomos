# 实验执行与记录准则 — 跑实验与留下可复算的记录

> 本准则约束「**跑一次实验**」的两端：怎么跑（§1）、留下什么记录（§2–§5）。
> 它是**判断层**文件：不配脚本、不设闸门、不计数。
>
> 🔴 **只管语义，不管 schema**：字段名与落盘结构由**各实验域的约定**定义。
> 本准则**不复制任何字段清单**——复制即产生第二真源。
>
> 🔴 **消费点真值 = 全库 `grep -rn "standards/09"`**（**不在此处枚举**：枚举必然漂移）。

## §1 实验生命周期（五个节点）

**设计 → 跑 → 记录 → 索引注册 → 收尾**

| # | 节点 | 判据（做到什么算完成） |
|:--:|---|---|
| 1 | **设计** | 跑之前能一句话说清「这次跑动要回答什么问题」；说不清 → 先别跑 |
| 2 | **跑** | 参数、规模、环境由该域自己的约定规定（本文不规定阈值） |
| 3 | **记录** | 见 §2–§5；**在跑的同一会话内完成**——隔会话补记即是考古，考古会失真 |
| 4 | **索引注册** | 产物登记到该域既有索引（实验记录索引 / 产物索引）；本文不新建索引设施 |
| 5 | **收尾** | 状态显式落定：有效 / 作废（写原因）/ 被取代（写取代者）。不长期停在「持续运行中」 |

## §2 记录要素（语义；字段名见各域约定）

任何一次有产物的实验跑动，其记录必须能回答下列**六问**。本文规定「要能回答什么」，
**不规定「字段叫什么」**——字段名与结构见各域约定。

| # | 要素 | 要能回答的问题 |
|:--:|---|---|
| 1 | **真源指针** | 记录里出现的每个数，从哪个文件读出来的？ |
| 2 | **口径** | 这个数是怎么算的？（规模与耗时尤其） |
| 3 | **规模** | 跑了多少？**且说清是哪个口径的多少** |
| 4 | **耗时** | 跑了多久？见 §3 |
| 5 | **产物位置** | 产物在哪、可否复得？（可再生件 vs 入版本库件的界线） |
| 6 | **状态** | 有效 / 作废 / 被取代；作废须写原因 |

> 🔴 **规模问的常见陷阱**：同一次 run 的规模在不同文档里可能记成多个数字。
> 差异往往源于「**登记条数**」与「**磁盘文件数**」是两个口径——生成按批提交，达标时同批中断，
> 在飞的 worker 仍会落盘。记录规模时必须同时说明取的是哪个口径，不要只写一个裸数字。

## §3 计时口径（语义）

1. **分步记，也记总计时**：能分开的步骤分开记，总计时 = 各步之和；不可分的实验记总计时即可。
2. **计的是墙钟**，不是名义值、估算值或整点快照。
3. **重跑与 resume 必须写明语义**：重跑（resume / 强制重算 / 换参数重画）把时间**累加到同一步**
   还是**记为新的一段**，由该域约定规定；且要区分「本进程耗时」与「台账累计值」——引用时别混。
4. **缺了就空着**：某步当时没记，记录里留空并注明「未记录」，**不推测、不回填**。
5. **禁止人工抄录**：耗时从台账/日志读，不从终端输出凭记忆抄。时间戳臆造在本项目已有实证
   （见 `CLAUDE.md` §会话边界规则）。

## §4 单一真源与可复算判据

1. **一个事实一个真源**：同一件事（如「这次跑了多久」）在项目里只允许有**一个机器可读的落点**；
   文档中出现它的地方是**引用**，不是副本。
   - 反例：同一耗时事实存在三套载体——约定的字段名、实现的变量名、临时新增的 JSON。
     三者并存时，读者无法判断哪个是权威。
2. **写判据，不写死数字**：需要写数字时**优先写「怎么复算」**（一条命令 / 一个指针），
   把数字本身当**快照**并标明取数时间。
   - 理由：写死的测量值从落笔起就在过期。
3. **人工列是生成物**：能从台账生成的行不要手写；手写列与台账冲突时**以台账为准**。

## §5 历史缺口的处理原则

1. **保持空缺**：没有记录的历史 run 就是没有；不为「看起来完整」而补写。
2. **能复算的可以补，但须注明来源与口径**（例：某步耗时可从 manifest 复算；
   另一些步骤无从复算 → 空着）。
3. **记一次「为什么缺」**：缺口本身是信息（当时的工具没记），比补出来的假数有价值。

## §7 退役判据（依 [06 §2-5](06_改进与维护宗旨.md)）

出现下列任一情形，本准则应退役：

1. 实验记录改由台账/索引**生成**（不再需要人写记录）⇒ §2–§5 失去对象；
2. 本文条款被某个工作流或域约定**整体吸收**（无独有条款）；
3. 项目长期不再按「一次跑动一份记录」组织实验。
