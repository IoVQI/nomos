# 科研汇报展示准则 — deck/PPT/PDF 的结构、溯源、保真与一致性要求

> 本准则约束**科研汇报材料**（Markdown deck → beamer PDF；含中英双版）的结构、溯源、
> 版式保真与派生件一致性。
> 它是**判断层**文件：不配脚本、不设闸门（依 `06_改进与维护宗旨.md` §3「自律设施默认拒绝」）。
> 约束方式是**被汇报类工作流引用为检查依据**——真值 = 全库 grep `standards/07`（消费点不在此枚举，防漂移）。
> 条款须附实践出处；无案例的条款不写入——本文的「反例」均来自一般化的汇报审阅经验，不指向具体项目。

## §1 结构（叙事弧与模块要点）

1. **叙事弧**：动机 → 对象/方法 → 核心结果 → 证据链 → 交叉验证 → 机制 → 拓展 → 结论边界。
   本准则 §1 为**判定基准真源**；汇报叙事审计工作流（若你的项目有）的「六维审计」为其**审计方法**
   （怎么查），判定以本准则为准。

2. **动机模块先引入、后展开**：在呈现具体现象之前，必须引入本汇报涉及的**核心效应与关键量**
   （定义 + 为什么要追）；符号首次出现应可追溯至定义处。
   - 反例：直接从结果页开始，听众不知道这个量为什么重要。

3. **残留/开放动作只列真实在办事项**：已废弃事项不得在成品中仍以开放动作出现。
   - 反例：某项作者沟通已结束，deck 与 tex 仍列在「待办」页。

4. **成品页面只承载内容与证据**：叙事弧、流程说明、**内部工作流用语**、**自我指涉的元评论**
   均属设计期/审计期语言，不得出现在成品页面上。
   判据：这句话是在描述**研究内容**，还是在描述**这份材料自己**？后者删。
   - 常见形态：
     ① 把「叙事弧」当展示内容——它是审计基准，不是听众需要看的东西；
     ② 使用项目内部叫法描述方法（台面上应说领域通用术语）；
     ③ 「（本汇报要判定的对象）」一类自我指涉；
     ④ 数据比对手法（数字化、重采样、插值）写在成品页——属方法记录，不是内容；
     ⑤ 向听众解释显而易见的事。

5. **收尾页只做礼节，不做自我评价**：致谢/结束页承载的是**礼节**（致谢、欢迎提问），
   **不承载对自己汇报的质量断言**——如「数据真实·脚本可复现·结论有边界」一类**产品发布式口号**。
   判据：这句话是**对听众说的**，还是**对自己的作品下评语**？后者删。
   - 反例：结束页写「本工作数据真实、结论有边界」，把汇报当成产品发布。

6. **首页标题：点明对象与工作，副标题只作范围限定**：展示材料 PDF 首页的**主标题**须能独立回答
   「研究对象是什么、做了哪项工作」；**副标题**只补**范围限定**（数据/方法/时间范围），
   不得是主标题的换词重述，也不得**仅是一张图表的指称**。
   禁用**无判定内容的规模词**：`全链路`、`全流程`、`体系`、`探索`、`若干问题` 一类——
   它们描述的是篇幅而非内容。
   - 判据：把标题念给一个没听过这项工作的人，他能否说出「研究了什么、做了什么」？不能则不合格。
   - 反例：主标题只有领域词，没有研究对象与工作性质；副标题只写「论文 Fig. X」，等于一张图的指称。

7. **章节标题描述「这一部分做了什么」，不描述「这份材料怎么组织」**：汇报地图与章节目录的标题，
   主语是**内容**，不是**叙述结构**。三类词须删：
   ① **内部工序用语**（`四层管线`、`全链路`）——项目内部叫法，见 §1.4 同族；
   ② **自我评价**（`自证可信`、`决定性排除`）——对自家工作下评语，见 §1.5 同族；
   ③ **叙事学词汇**（`叙事弧`、`反转弧线`）——描述叙述结构而非内容，见 §1.4 同族。
   - 判据：标题里的每个词，能否回答「听众会在这一部分看到什么」？答不出者删。

## §2 溯源（文献衍生内容的引用与标注）

1. **引用论文图用原文图**：数字化重绘件不得替代原图承担「论文侧证据」角色；
   重绘件用于定量对比时须显式标注派生性质。
   - 反例：用数字化重绘的曲线声称「论文给出的结果」，读者无法判断差异来自论文还是重绘。

2. **元信息格式**：每处文献衍生内容必须携带来源与置信度，统一格式：
   `Source: <Authors> (<Year>), <Journal> <Vol>, <Page>; arXiv:<id>; <derived-nature> (confidence <A/B/C>)`
   derived-nature 四选一：`digitized re-plot` / `vector extraction` / `published value` / `original screenshot`。

3. **承重引用可溯源**：构成结论依据的他人工作，在 deck 内以「主要参考」帧/节给出完整元信息。
   - 反例：正文只写作者姓氏，成品中找不到完整引文。

4. **deck→tex 保真**：格式转换不得静默丢失内容（引用行、关键数值、图注）；
   转换后以「deck 引文串必须 tex 同命中」类断言核对。
   - 反例：deck 中唯一的完整引文没有进入 tex/PDF。

5. **涉他方已发表工作的表述分寸**：分歧叙述限于「**我方未复现**」这一事实陈述；
   **不得在成品中预判对方工作的性质**（如「对方数据/绘图有问题」）。理由有二：
   展示场合不宜，且该预判在证据上本属未判定项——留作内部记录，不上台面。

## §3 版式保真（编译产物断言 + 目视核）

1. **文本层断言**：编译产物须过关键串断言——应出现的值必须命中；被否定的旧值必须 **0 命中**。
   - 反例：旧数值残留、新数值缺失，编译却成功。

2. **关键页渲染目视**：含新增/改动帧与末页；检查溢出与裁切（超右缘、页脚边界吃字）。
   - 反例：图表或 alertblock 被整体裁掉，只剩残字；表格列/导航条截断。
   - 🔴 **「Overfull 归零」不是版式合规的证据**：编译日志的 `Overfull \hbox/\vbox` 计数
     **抓不到一整类布局缺陷**。反例——某帧 `\end{tabular}` 后缺空行，后续正文被接在同一行、
     整体顶出右缘外，**而日志报 0 条 Overfull**。`\vspace` 在水平模式下不产生换段，挡不住这个问题；
     唯一可靠的检出方式是**渲染目视**。
     ⇒ 纪律：**日志计数只作辅助，判定以目视为准**；两者冲突时信目视。
     凡下「版式已合规」结论，必须说明目视覆盖了哪些帧。

3. **LaTeX 特殊字符转义**：正文文本中的 `%`、`&`、`#`、`_` 必须转义；
   断言应含「裸 `%` 被当注释吞尾」类检查。

4. **字形覆盖断言**：字体覆盖区外的符号/emoji 进成品前**必须经探针 `.tex` 验证**；
   「编译通过」不构成证据。
   - 背景：模板可能指定某一 CJK 字体族（如 Fandol 系列），其实际覆盖 = **CJK + 拉丁/数字/常用标点**；
     区外字符被 xelatex **静默丢弃**（不报错、正文只留一个空档），且该消息非 `! ` 致命错误，
     编译闸门放行；§3.1「文本层断言」也挡不住——缺字落在**装饰/编号字符**上，
     其所在长串的断言仍照常命中。
   - **判据（哪些符号必须先验证）**：凡**非 CJK、非拉丁/数字/常用标点**的字符——
     圈号 `①`–`⑩`、箭头 `⇒`、几何/星形符号 `▲ △ ▶ ● ★`、以及**一切 emoji**（`⚠️`/`🔴` 等）——
     进入成品 `.tex` 前一律先探针验证。
   - **做法（探针 `.tex` 最小可执行形式）**：候选符号各印一遍，一次 `xelatex` 即可：
     ```latex
     \documentclass{article}
     \usepackage{ctex}
     \usepackage{amssymb}
     % 在模板实际使用的字体族下测试：
     % \setCJKmainfont{<你的正文字体>}
     % \setCJKsansfont{<你的无衬线字体>}
     \begin{document}
     正常符号：※ $\blacktriangleright$ $\ast$ \textcircled{1} $\Rightarrow$
     待测符号：⚠ 🔴 ① ② ⇒ ▲ △ ▶ ● ★
     \end{document}
     ```
     编译后取缺字**全集**（勿只看 stdout 摘要）：
     `grep -o "Missing character: There is no .* (U+[0-9A-Fa-f]*)" probe.log | sort -u`。
   - **正解写法**：圈号 `①`–`⑩` → `\textcircled{1}`…`\textcircled{10}`（数字在覆盖区内，圆圈由 TeX 画）；
     emoji → `※` 或 pifont `\ding{N}`（须 `\usepackage{pifont}`）；字面 `⇒` → `$\Rightarrow$`。
     优先沿用模板中已验证可用的写法，不另起一套。
   - **为什么「编译通过」不算证据**：`latexmk` 的 stdout **摘要**只印前几条缺字消息，其余折叠为
     「`And N more --- see log file`」——静默丢弃被整批漏看；须读**完整 log**或按上条 `grep` 取全集。
   - **收尾断言（🔴 缺字必须「直数」，不得用间接信号）**：**判据 = 编译日志 `Missing character` 行计数 == 0**——
     `grep -c "Missing character" <compile>.log`（⚠️ 计数为 0 时该命令退出码为 **1**，勿写成 `cmd && next`）。
     「编译通过」「`! ` 无致命错误」「目视未见空档」**都不是证据**：区外字符被 xelatex **静默丢弃**，
     上述信号一律照常放行。直数通过后，仍须逐帧渲染目视确认编号**真的显示了**——
     直数归零只证「字体里有这个字形」，不证「它落在正文里」（与 §3.2「判定以目视为准」同族）。

## §4 派生件一致性（单一真源与副本同步）

1. **单点真源**：跨件复用的数据/格式串收敛到单点定义（数据模块/样式助手），禁副本内嵌。
2. **跨件一致**：同一数值/标签在 deck/讲稿/成品/tex/图注/登记表中的出现必须一致；
   修改须枚举**全传播面**（含已提交引用）。
3. **副本同步**：平台副本（如交付目录）与源逐字节同步；登记表为唯一登记点（不另建第二登记）。
   - 反例：图注格式不统一，部分图有来源脚注、部分没有。
