# coordination/handoff/ — 跨会话交接提示词

> **用途**：把「本会话做完的事 + 下一会话该做什么」写成一份**自包含提示词**，用户直接粘给新会话即可。
> **它解决什么**：会话之间没有共享记忆，唯一媒介是文件系统。没有本目录时，交接提示词散落在各任务目录，
> 无统一命名、无入口索引——下一条该放哪、上一条还在不在，都没有人能回答。

## §1 与 `../claims/` 的分工（别混）

| 目录 | 场景 | 时序 | 防的是 |
|---|---|:---:|---|
| `handoff/`（本目录） | **串行交接**：A 会话结束 → B 会话开始 | 前一个已停工 | 信息丢失 |
| `../claims/` | **并行协调**：A、B 同时开工 | 同时在线 | 写入碰撞 |
| `ai_system/workflows/parallel_session_launch_workflow.md` | **上游触发器**：判「该不该并行 / 该不该交接」，并定**执行载体**（子代理 / teammates / 独立会话 / 单干） | 决定**之前** | 选错协作形态 |

两者都靠文件系统传信息，但是**两件事**。串行不需要写域声明（前者已停工），并行不需要长篇交接（后者自己能看现场）。

> ⚠️ **例外**：消费交接提示词的会话**可能同时是并行会话之一**（前者已停，但另有会话在场）。
> 串行交接不豁免并行协调——消费方仍须先写 `../claims/<slug>.md` 声明写入域
> （先写后查，见 `../claims/README.md` §3 铁律 2/7），再开工。

## §2 目录约定

```
coordination/handoff/
├── README.md      # 本文件（约定单点真源）
├── index.md       # 提示词清单（活跃 + 留档）
├── active/        # 活跃交接提示词 —— 真值：ls coordination/handoff/active/
└── consumed/      # 已被消费的留档（供追溯，不删）
```

## §3 何时写

- 会话自然结束，且有未完成工作要移交
- 任务中途需要用户另开会话继续
- 用户显式要求「写个提示词给下个会话」

## §4 命名与骨架

**文件名**：`<YYYY-MM-DD>_<task_slug>.md`
日期用 `python ai_system/validation/beijing_time.py --fmt date` **现场取**，禁止臆造或凭记忆回填。

**骨架四要素**（缺一不可，这就是「自包含」的定义）：

| # | 要素 | 说明 |
|:--:|---|---|
| 1 | **任务** | 一句话说清做什么 + 完成判据（可验证的，不是「做好」） |
| 2 | **先读** | 权威真源清单（文件 + 读哪一段），标明哪个是单点真源 |
| 3 | **已确立的事实** | 跨会话**不要重新推导**的结论——每条**必须带来源锚点** |
| 4 | **硬约束与已知的坑** | 踩过的别再踩；含 CI 门禁、并行会话、编码/行尾等 |

可选：任务分解与选型、验收标准、方向提示（须标明「勿据此下结论」）。

## §5 🔴 事实复述的纪律（本设施最大风险）

提示词**会复述事实**（这正是它的价值），但复述即副本，副本会漂移。硬性要求：

1. 每条复述的事实**必须带来源锚点**：文件路径 + 章节、commit hash、或产物路径。
2. 文件头记**生成时间 + 生成时的 HEAD commit**，消费方据此判断要不要回源核对。
3. 消费方开工第一步是**回源核对**（对照 §「先读」列的权威真源），不是直接采信提示词。
4. **事实真源在仓库的正式文档里**（`proposals/`、`ai_system/`、`project/`）；提示词是**操作入口**，不是真源。
   真源变更时提示词可能已过期。
5. 🔴 **资产的存在性另有专表时，锚点须指向专表而非目录**：复述「某目录里有 X」时，
   **目录存在 ≠ 资产存在**。实证：一份提示词称某目录含「方法核 + 推导补充 + 复现计划」，
   实盘该目录只有其中一项——消费方因此先写了一轮错误的「开工先读它」。

## §6 生命周期

```
active/  --(被消费 / 任务完成 / 作废)-->  consumed/
```

1. 写完 → 落 `active/`，**同批**在 `index.md` 登记
2. 消费完成 → 移入 `consumed/`，`index.md` 状态改「已消费」并注明消费会话与结果
3. 作废 → 同样移入 `consumed/`，状态标「已作废」**并写明原因**（否则后人不知道为什么被弃）

## §7 消费点（让设施活着）

新会话开工时，若用户提到「交接 / 上个会话 / 提示词 / 接着做」→ **先 `ls coordination/handoff/active/`**。

入口已写入 `CLAUDE.md` §会话边界规则。没有消费点的目录会变成没人读的死目录。
