# coordination/claims/ — 并行会话协调

> **用途**：多个会话同时改同一个 repo 时，靠**写入域声明**避免撞车。
> **它不是什么**：不是聊天室，不是共享收件箱。**共享可写文件本身就是冲突源**——本设施的核心只有一条：**每个文件在任何时刻只有一个写者**。
> **「不设共享收件箱」≠「不能通信」**：跨会话消息通道**瞬时不落盘**，不构成共享可写文件，故与本条不冲突——它是**检测层**，不是约束层，见 §3.5。
> **与 `../handoff/` 的分工**：本目录管**并行**（A、B 同时在跑，防写入碰撞）；`../handoff/` 管**串行**（A 停了、B 接手，防信息丢失）。
> **上游**：本目录管「**怎么并行**」；「**该不该并行**」的判断在 `ai_system/workflows/parallel_session_launch_workflow.md`。

## §1 要防的四件事（都有实证，不是假想）

| 事故 | 实证 |
|---|---|
| 无路径 `git commit` / `git add -A` 卷走他会话未提交件 | 索引文件被整份带入他人提交 |
| cleanup 脚本把他会话的文件当遗留物删掉 | 跨日并行会话互删对方的临时标记文件 |
| 声明迟到 ⇒ 双方都得到「无冲突」的假阴性 | 两会话撞车后才由用户裁决提交顺序（见铁律 2 反例） |
| 共写生成物单侧提交 ⇒ 树不自洽（CI 红） | 一份由台账生成、两会话状态行同表的索引（见铁律 8） |

## §2 目录约定

```
coordination/claims/
├── README.md      # 本文件（约定单点真源）
├── _TEMPLATE.md
└── <slug>.md      # 每会话一个独占声明文件 —— 真值：ls coordination/claims/*.md
```

**🔴 不设汇总表。** 汇总 = 读 `claims/*.md` 的状态字段（见 §4 的一行命令）。汇总表是共享写点，正是本设施要消除的东西——设了它，就等于把冲突源又请回来。

## §3 铁律

1. **单写点** — `claims/<slug>.md` **只由该 slug 的会话写**。任何文件任何时刻只有一个写者。

2. **声明先行** — 改任何文件**之前**，先把路径写进自己的 claim「写入域」。发现自己要改的路径**已被他会话声明** → **停止并上报用户**，不自行合并、不自行覆盖、不「顺手改一下」。
   > 🔴 **写入域必须覆盖「产出去向」，不只源码路径。** 曾实证：某会话声明了脚本源码路径却漏了脚本的**输出目录**，而它确实在写那里——声明缺口会让他会话（如做清理的会话）误判该路径无人占用。
   > 自查一句话：**「我的脚本会往哪些目录写文件？」**，把这些目录一并写进写入域。
   > 🔴 **开工动作序列（只查不写 = 对后来者隐形）**：
   > ① **先写**自己的 claim（含写入域清单）→ ② **再查**他人 claims 有无交叠 → ③ 有交叠则上报用户。
   > 反例：某会话开工先查 claims（当时现存声明均已结项）判定无冲突，40 分钟后才补写自己的声明；
   > 期间另一会话开工查 claims 同样得到「无冲突」——两会话撞车后才由用户裁决提交顺序。
   > **先写后查 = 后来者一定看得见你在场；先查后写 = 后来者看到的是一个空目录。**

3. **共享索引单写** — 各 `index.md`（`ai_system/index.md`、`project/index.md`、`proposals/index.md`、
   `ai_system/official_docs/index.md`、`.claude/skills/README.md`、`.claude/workflows/README.md` 等共享注册表）
   由**主会话**统一收口。无主会话时：会话只读，把待登记项写进自己的 claim「待办」，由收口会话批量处理。
   > 🔴 **实证：共享表里的一个错链，会被下游当成事实。**
   > 一天内多次改写同一张表时，「详情链接」这类**手写引用字段**很容易被顺手改错。当时只是链接指错，
   > 看着像显示问题；但随后的**台账迁移**拿这条链接做「文件 → 编号」绑定，照单全收 ⇒
   > 一份正文被挂上错误的 id 与状态。**显示错误升级成了状态记录错误。**
   > **两条纪律**：① 改共享表的引用字段**前**，先打开目标文件核对「它确实是这条目该指向的东西」，
   > 不要按"最新那个文件"猜；② 跨会话密集改表**后**，抽检引用字段与目标内容是否指同一事项。
   > 推广：任何「引用字段 → 结构」的导入（迁移、索引重建、生成器）都必须带这道核验，
   > 否则**上游的单点手误会被放大成下游的结构化事实**。

4. **git 精确路径** — 禁用 `git add -A`；commit 前 `git diff --cached --name-only` 逐条确认；发现他会话文件 → `git restore --staged <path>`。
   > 🔴 **作用域边界：「从索引移除但保留磁盘文件」这一子类不适用本条。**
   > 凡 `git rm --cached`（摘出跟踪 / 去版本化 / 存量产物不入 git）的提交，
   > **不得**走 pathspec 式（`git commit -- <paths>` / `--pathspec-from-file`）：
   > 该式按「HEAD 树 + **该路径的工作区内容**」重建命名路径，而 `--cached` 只移出索引、**文件仍在磁盘**
   > ⇒ 该路径被读作「无变化」，删除被**确定性还原**（非竞态），且原 index 中**已暂存的删除一并丢失**。
   > ⇒ 该子类**按 index 整体提交**（`git commit` 不带 `-- <路径>`）。此时**唯一有效的处置是串行化**：
   > 先确认对端会话已落定（`ListAgents` + `git status --porcelain`）再提交，**勿依赖复核快照**。
   > 提交后仍须按 `git show --name-status HEAD` 的 `A/D/M` **分类计数**核对（勿只看 `files changed` 总数——
   > 删除被静默还原时该总数偏小却不报警）。
   > 🔴 **已知坑：pre-commit 的 stash 会让 hook 看不见他会话未提交的共享索引 ⇒ 假 FAIL。**
   > `pre-commit` 跑 hook 前会 `git stash` 掉**所有未暂存改动**。若他会话改了**被 hook 读取的共享文件**
   > 且**尚未提交**，它会被一并 stash 走，hook 于是看到 HEAD 旧版。
   > **判据**：`git show HEAD:<该文件> | grep -c <他会话刚加的行>` 为 `0`，而磁盘上确有该内容。
   > **规避之一**：等他会话提交其共享索引后再提交。
   > **规避之二（拆批提交）**：按各 hook 的 `files:` 触发模式把批次**拆开**——`git diff --cached --name-only`
   > 与每个 hook 的 `files:` 前缀逐一对照，选出**不含任何触发前缀**的文件先提交（对应钩子不触发），
   > 被阻塞文件留待解封后补交。
   > **不要用 `--no-verify` 绕过**（**指假 FAIL 场景**）——那是把假红灯换成真盲区。
   > **救援例外**：当动机是「**不把他会话的大批在途件拖入 stash 循环**」时可用 `--no-verify`，
   > 但**三条件须同时成立**：① 提交面**不含行为性改动**（纯文档 / 台账 / 声明）；
   > ② **适用闸门已手动跑过并全绿**（在 commit message 中逐项列明）；③ 动机写进 commit message。
   > 三缺一 ⇒ 回到正常钩子路径，或等对方提交后再走。
   > 🔴 **注意**：`pass_filenames: false` 类**读工作区**的闸门（本骨架的 `check-workflows` /
   > `check-official-docs` 即是）**不受「改动即暂存」保护**——判据是「**本笔提交面是否包含该文件**」，
   > 而不是「该文件是否已暂存」。处置同上：拆批 / 等对端 / 经授权并入。

5. **不碰他会话的未跟踪文件** — 未跟踪件 = 在途工作。移动、删除、提交都算干扰。

6. **不臆造他会话的状态** — 想知道别人在干什么，读 claim；claim 没写就是不知道，不要从 git 状态反推。
   > `ListAgents` 只回答「**谁在线**」，不回答「**在做什么**」；`idle` 是调度状态，
   > 不是「此人闲着没活」。它不能替代 claim——意图真源仍是 claim，见 §3.5。

7. **`claims/` 干净 ≠ 无并行会话** — 它只说明「无人（按时）声明」（声明可迟到，见铁律 2 反例）。
   触及**共享索引 / 生成物 / 校验脚本**之前，开工核查加三步：
   - `git status --porcelain` — 有没有你没做过、却已暂存/已改动的文件；
   - 共享区 mtime 扫描（`ls -lt <共享目录> | head`）— 有没有你不认识的近期写入；
   - **问对等会话本人**：`ListAgents` 列出本机对等会话（含 `idle` 状态）→ 用
     `SendMessage` 问「是否在跑、写入域是什么」。**取代「直接问用户」作为首选**——用户可能不知道
     （并行会话是隔天开的、或忘了），而对端能自答，且答的是它自己的写入域声明。
     **无对等会话 / 无人回应 → 回落问用户**（用户仍是第一手信息源）。⚠️ 通道**不持久**，对端可能已停
     ——**无回应 ≠ 无人**，须回落而非据此判「安全」。对端回答属「**他会话自述**」，不是事实真源，
     须连时间戳记进自己的 claim（消息不落盘，claim 落盘）。
   > 三步用于判断「**有没有人在写**」；对方的**任务与意图**仍只能来自 claim 或用户/对端自述。
   > 三步任一步有异常信号 → 按「有并行会话」处理。

8. **共写生成物不可分** — 「生成物 + 其生成器 + 其输入（真源）」是一个**不可分的提交单元**：
   单侧提交的树可能不自洽（索引由全部台账生成、两会话的状态行同表 ⇒ 一致性闸门直接红）。两会话共写同一生成物时：
   - 最优：**先落一方批次**——等其提交完成后再改自己一侧；
   - 已同时改：`git stash push -- <自己的真源文件>` → 以对方状态重渲染生成物 → 提交对方批 →
     `stash pop` → 重渲染 → 提交自己批。

9. **claim 时间戳实时取钟** — claim 里每个时间字段（开始时间 / 最后更新 / 变更记录行）都**当场取钟**，
   不允许凭印象、不允许事后回填、不允许填整数：
   ```bash
   python ai_system/validation/beijing_time.py --fmt header    # 2026-09-12 01:26（开始时间 / 最后更新）
   python ai_system/validation/beijing_time.py --fmt hhmm      # 0126（变更记录行）
   ```
   事后需要核对的，以自己那笔提交的 `%ci` 为准（`git show -s --format=%ci <hash>`）。
   > 实证（同族复发 2 次 ⇒ 规则文本已失效，故此处配可执行命令）：某会话自陈「claim 中臆造时间戳」；
   > 另一会话 claim 填 `01:05`，而其提交的 `%ci` 为 `00:36:30`——偏差由**并行会话**核出。
   > 模板侧已改为「不跑脚本就填不出合法值」的占位符。

## §3.5 跨会话消息通道（检测层）

**它是什么**：`SendMessage` / `ListAgents` —— 跨会话消息能力，让**本机上的独立会话**互为可达
（跨机器需 Remote Control）。

**它不是什么**（三条边界，缺一即误用）：

| 边界 | 说明 |
|------|------|
| **信道 ≠ 约束** | 它让你**知道**冲突，不**阻止**冲突。「每个文件只有一个写者」仍由写入域声明 + 铁律 2 承担 |
| **瞬时不持久** | 对端可能已停。**无回应 ≠ 无人**——不得据「发了没回」判定「无人占用」 |
| **在线 ≠ 意图** | `ListAgents` 给的是**在线/调度状态**，不是「在做什么」。意图真源仍是 claim（铁律 6） |

**用法**：开工核查第 3 步（铁律 7）以它为首选；问到对方的写入域后**记进自己的 claim**
（消息不落盘，claim 落盘）。**不为自己开常驻监听**——会话是短生命期的。

## §3.6 内部派单：子代理与 teammates（执行层）

> **与 §3.5 的分工**：§3.5 管**跨会话消息**（独立会话之间，检测层）；本节管**单会话内派单**
> （主会话用 `Agent` 起子代理 / teammates——它们**不是**独立会话）。两者都**不是约束层**：
> 写入域纪律仍由 §3 铁律 1/2 承担。

| 形态 | 怎么起 | 关键差异 |
|---|---|---|
| **会话内子代理** | `Agent`，**不带** `name` | 结果一次性**完整**回传 + 带 usage；报告**不直接给用户** |
| **teammates** | `Agent`，**带** `name` | 🔴 长结构化回传**会被截断**；**不提供 usage**；会主动宣告可续跑 |

🔴 **四条纪律**（不因「是我自己派的」而豁免）：

1. **写域仍须显式分配**——派单者全知，故**不需要** claim 做发现，但**需要**把各路写成互不相交，
   且**派单前后把清单记进自己的 claim**（claim 是落盘留痕）。
2. **不得因载体便利而放宽「每个文件一个写者」**——铁律 1 与载体无关。
3. **代写共享索引仍归主会话**——铁律 3 的收口职责不因派单而转移；子代理需要登记就回报主会话。
4. **交付数值文本时，口径须随数一起写死**——凡**相对量**（百分比 / 比值 / 增长率 / 偏差 / 「差多少个 σ」），
   必须把**分子、分母与参考侧**一并写出，不能只给一个数。**子代理看不到主会话已有的口径**
   （它只收到「给我画一张图」），而百分比的分子分母是**隐式约定**——不写就会各写各的。
   > **实证**（唯一证据，可复算）：同一份交付物中，注记写「+23%」（分母 = 论文值）而正文表写「−29.6%」。
   > 两者**都不算错**，但同一个量摆出两个数，读者会当成两个结论。主会话复核后**定单一口径**，逐格对齐。
   > **主会话侧同责**：搬入子代理 / 对端交付的数值时**逐格复核口径**，不只看数值是否相同
   > ——**数值相同而口径相反 = 结论相反**。

## §4 用法

**用户侧**：开并行会话时给一个 slug（如 `parser` / `docs`），并告知它先读本文件。

**会话侧**：

1. **开工第一步** — 复制模板并填「写入域」（🔴 顺序：**先写自己的 → 再查他人的 → 有交叠即上报**，见铁律 2；
   触及共享文件时加三步核查，见铁律 7）：
   ```bash
   cp coordination/claims/_TEMPLATE.md coordination/claims/<slug>.md
   ```
2. **期间** — 写入域变化时更新 claim
3. **结束** — 填「产出 / 交接」+ commit hash，状态改 `✅ 已完成`

**复核**（commit 前 / 收口时）：

```bash
# 🔴 只取「状态行」——**勿用全文件 grep**：每个 claim 都含模板图例行与「写入域」段标题，
#    全文件匹配会命中**所有**文件 ⇒ 信号被噪声淹没（且随 claim 数增长）。
#    判据：命中行数应**恰等于** `ls coordination/claims/*.md | wc -l`（1 行/文件）。
grep -H '^- \*\*状态\*\*' coordination/claims/*.md
```

> 🔴 **已知局限**：claim 的「✅ 已完成」是纯自律——`claims/` **无任何机械兜底**（脚本层零消费者）。
> ⇒ 会话若在收尾前退出，其 claim 将**永久停在「🔄 进行中」**，且因**铁律 1**（claim 只由该 slug 写）
> **无救济路径**——他人不得代写。
> **处置：登记为已约束，不新增闸门**——该状态**不阻塞任何流程**（claim 是给人读的协调面，不是闸门输入），
> 而为其建检查器属「为保险起见加个校验」，且**假防线比无防线更危险**。

## §5 何时不用 / 何时该开

> 🔴 本设施管「**怎么并行**」（协议）；「**该不该并行**」的判断在
> `ai_system/workflows/parallel_session_launch_workflow.md`（触发器层真源）。
> **判据与三态输出不在此重复**——此处只留导航，防第二真源。

**判据速览**（详规见上述工作流）：

| 条件 | 含义 |
|---|---|
| 宽 | 可拆出 ≥2 条候选工作流 |
| 写域不相交 | 候选之间（含共享层）两两无交叠 |
| 够长 | 单条工作流长到能摊薄协调成本 |
| 阻塞等待 | 主线卡在慢 I/O（CI / 长扫描 / 批量下载） |

`可并行 = 写域不相交 ∧ (够长 ∨ 阻塞等待)`，且候选数 ≥ 2。

**何时不用**：

- 只有一个会话在跑 → 不需要
- 已用任务卡把写入域天然隔开（一人一份产出）→ 用那套即可，本设施是兜底
- 纯只读会话（调研、审计不落盘）→ 不需要
