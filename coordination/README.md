# coordination/ — 多会话协调设施

本目录承载**多个 AI 会话同时或先后在同一个仓库上工作**时的协调协议。

会话之间没有共享记忆，**落盘信息是唯一的媒介**。本目录就是那个媒介。

## 两种场景

| 子目录 | 场景 | 何时用 |
|---|---|---|
| `claims/` | **并行协调**（A、B 同时开工） | 被指派为并行会话 → 开工第一步写 `claims/<slug>.md` 声明写入域 |
| `handoff/` | **串行交接**（A 结束 → B 接手） | 用户提到「交接 / 上个会话 / 接着做」→ 先读 `handoff/` 下的活动交接单 |

## 核心纪律

**每个文件在任何时刻只有一个写者。**

- 要改的路径已被他会话在 `claims/` 中声明 → **停止并上报用户**，不得自行合并。
- 共享索引（如各 `index.md`）由**主会话单写收口**。
- 交接单复述事实时**必须带来源锚点 + 生成时 HEAD**——复述即副本，副本会漂移。

## 与其他设施的关系

- 决策层：`ai_system/workflows/parallel_session_launch_workflow.md`（该不该开并行、怎么拆）
- 执行层：`Skill: parallel-session-check`（做分解、出写域图）
- 落盘层：本目录

> 本目录替代了早期项目中藏在 `sandbox/` 下的 `_parallel/` 与 `_handoff/`——协议本身是治理设施，不该埋在沙箱里。
